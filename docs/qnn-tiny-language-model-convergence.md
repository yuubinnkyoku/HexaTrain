# QNN HTP tiny language model convergence study

## Result

This bounded study did not establish an HTP setting that meets the additional convergence condition. The result is `GOAL_PARTIAL_SUCCESS`: every permitted CPU configuration and HTP finalist was evaluated, one-step Momentum and Adam optimizer graphs are correct, but repeated HTP updates eventually become non-finite. The success thresholds were not relaxed.

The model remains `B=1, T=8, V=32, D=16`, one head, one pre-norm layer, `FFN=32`, ReLU, causal FP32. It uses one-hot token embedding, fixed sinusoidal position values, separate trainable token/output matrices, and the same four deterministic rule families. Training uses phase 0 and evaluation uses phase 1; no evaluation sequence or future token enters training input.

## Diagnosis and bounded search

Diagnostic trajectories now include correct-token mean/median probability, entropy, mean/minimum logit margin, global gradient/update/parameter norms, update-to-parameter ratio, and per-parameter gradient/update/parameter norms and maxima at the requested checkpoints. The parameters covered are token embedding, Wq/Wk/Wv/Wo, both LayerNorm gamma/beta pairs, FFN W1/W2, and output projection.

The published SGD baseline on CPU showed that 100 steps were too early:

| Steps | Median evaluation loss reduction | Seeds at accuracy >= 75% |
|---:|---:|---:|
| 100 | 2.0024% | 0/5 |
| 320 | 13.9134% | 0/5 |
| 640 | 51.7172% | 0/5 |
| 1000 | 75.0473% | 5/5 |

The bounded search counts were 48 SGD CPU configurations, 3 SGD HTP finalists, 24 Momentum CPU configurations, 2 Momentum HTP finalists, 12 Adam CPU configurations, and 2 Adam HTP finalists. All CPU sweeps replay deterministically.

CPU winners were:

- SGD: `lr=0.1`, 1000 steps, initialization 1x, deterministic shuffle; median reduction 99.9056%, 5/5 at 75%.
- Momentum: `lr=0.01`, momentum 0.95, 1000 steps, fixed order; median reduction 98.8019%, 5/5 at 75%.
- Adam: `lr=0.003`, 320 steps, fixed order; median reduction 94.5603%, 5/5 at 75%.

All three optimizers diverged on repeated HTP updates. SGD `lr=0.1` was classified `OVER_UPDATING`. Momentum amplified the accumulating CPU/HTP gradient difference. Adam improved loss substantially before divergence: the `lr=0.003` candidate reached batch loss 0.532 and batch accuracy 1.0 at step 100; the `lr=0.001` candidate reached batch loss 1.10 and batch accuracy 0.75 at step 200. Both later produced non-finite parameters. The overall classification is `NUMERICALLY_UNSTABLE_REPEATED_UPDATES`, not dataset leakage or CPU fallback.

## Dataset and boundaries

The four patterns are 0–3 repeating, 4–7 repeating, 8/9 alternating, and 10–12 repeating. Input frequency is `0:2,1:2,2:2,3:2,4:2,5:2,6:2,7:2,8:4,9:4,10:3,11:3,12:2`; target frequency is `0:2,1:2,2:2,3:2,4:2,5:2,6:2,7:2,8:4,9:4,10:2,11:3,12:3`.

CPU constructs token/target one-hot tensors, selects batches, controls graphs, calculates stable cross-entropy scalars and Adam bias-correction scalars, copies fixed buffers, and runs the independent reference. HTP performs embedding arithmetic, Transformer forward/backward, logits, Softmax, cross-entropy `dLogits`, parameter gradients, and optimizer arithmetic. The QNN CPU backend is not initialized; “CPU fallback” is false.

Performance and four-pattern final-optimizer inference are `NOT_REACHED`, because they were gated on satisfying the additional convergence condition. The previously published single-rule SGD inference remains a passing regression.

Public aggregates are generated by `scripts/export_public_tiny_lm_convergence_results.ps1`. Raw reports remain ignored under `build/reports`; callback/logcat text, device endpoints, private paths, binaries, APKs, and raw tensor dumps are excluded.
