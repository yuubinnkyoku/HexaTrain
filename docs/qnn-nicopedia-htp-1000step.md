# Nicopedia real-text HTP training: 320 vs 1000 steps

## Scope

This milestone extends the L19 seed-1 Nicopedia real-text model from the
existing 320-step HTP checkpoint to 1000 steps, evaluates the checkpoint, and
compares generation behaviour at the two step counts under identical sampling
conditions.

## Training

The 1000-step run is a from-scratch reproduction on QNN HTP:

- seed=1, layers=19, heads=2
- batch_size=8, learning_rate=0.003
- cache_context=32, cache_vocabulary=256
- training order hash preserved by `nprtTrainingOrder` (deterministic per seed)
- QAIRT SDK: `C:\Qualcomm\AIStack\QAIRT\2.48.40.260702`
- Build ID: `2.48.40.260702151143`

```powershell
scripts/run_nicopedia_htp_training.ps1 -Layers 19 -Seed 1 -Steps 1000 `
  -QairtSdkRoot "C:\Qualcomm\AIStack\QAIRT\2.48.40.260702" `
  -ExpectedBuildId "2.48.40.260702151143"
```

## Teacher-forced evaluation

| checkpoint | source | validation NLL | validation perplexity | validation top1 | development NLL |
|------------|--------|---------------:|----------------------:|----------------:|----------------:|
| L19 seed1 step 320 | HTP | 2.907504125 | 18.34 | 0.3005 | 2.923765110 |
| L19 seed1 step 1000 | CPU anchor | 2.510798771 | 12.31 | 0.3291 | 2.599144534 |
| L19 seed1 step 1000 | HTP | 2.553278928 | 12.85 | 0.3246 | 2.619808501 |

The HTP step-1000 validation NLL is within ~0.04 of the CPU anchor and ~0.35
better than the step-320 HTP checkpoint.

## Generation comparison

### Step 320 HTP generation

- Published successful run(s): SUCCESS, parity and AR gates PASS.
- Parity-control runs that do not pass the generation gate are not published as
  step-320 generation results.

Aggregate byte-level statistics are in the published bundle.

### Step 1000 HTP generation

- **BLOCKED by the CPU/HTP parity gate** for both greedy and sample modes.
- The fixed 2e-2 absolute logit-error gate is exceeded after 1000 steps.
- Cosine similarity between CPU and HTP logits remains above 0.999998,
  argmax/top-k agreement is preserved, and probability error stays small,
  so the divergence is consistent with growing logit magnitude exposing HTP
  backend rounding at lower effective precision rather than a training
  correctness bug. This does not identify the HTP internal datatype.

### Step 1000 CPU generation

Because HTP generation is blocked, CPU reference generation was produced for
quality comparison. Only aggregate statistics are published.

- greedy, max 64 bytes: still repetitive (`た` loop) but richer than step 320
- sample, max 128 bytes: visibly higher quality than step 320 sample

See `docs/results/qnn-nicopedia-htp-1000step-generation-2026-08/`.

## Parity audit details

Selected parity-row metrics for the first fixed prefix:

| metric | step 320 | step 1000 |
|--------|---------:|----------:|
| logits max abs error | 0.0111 | 0.0308 |
| logits mean abs error | 0.00181 | 0.00322 |
| logits RMS error | 0.209 | 0.416 |
| logits max relative error | 6.10 | 175.12 |
| logits cosine similarity | 0.99999978 | 0.99999872 |
| CPU logit RMS | 3.214 | 3.569 |
| probability max abs error | 0.00141 | 0.00300 |
| last argmax match | true | true |
| top-k set overlap (k=5) | 5/5 | 5/5 |

The absolute error grows roughly in proportion to the logit scale, while the
ranking topology remains stable.

## Limitations and next work

- HTP step-1000 generation is blocked by the existing parity gate; relaxing the
  gate requires a policy decision and is not done here.
- The evaluation uses the private Nicopedia cache (not in Git).
- The comparison bundle publishes aggregates only; full generated text remains
  private.
